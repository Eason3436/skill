結論

網格引擎本身幾乎沒有方向偏好——多頭與空頭網格賺到的「網格利潤」相差不到一個百分點。收益率的全部差距來自那筆你沒在看的持倉浮虧。

在這段樣本裡空頭網格帳面上贏（30 天平均 +1.43% vs 多頭 −0.39%），但那是因為期間本身偏空。把真實下跌路徑做幾何鏡像後再測，空頭網格面對同樣幅度的逆風反而虧得更多。所謂「空頭網格比較穩」是取樣造成的錯覺。

三個數字

01

怎麼測的

回測模擬的是 OKX 網格機器人的實際掛單狀態機，不是簡化的「穿越價格就算成交」：每筆買單成交後，會在上一格掛出對應賣單；賣單成交後在下一格補回買單。多頭網格的倉位永遠 ≥ 0，空頭網格永遠 ≤ 0，價格離開區間就停止成交、抱著倉位不動——和真實 bot 沒設止損時的行為一致。

網格區間取開始日之前 30 天的最高最低價，避免用未來資訊設參數。多頭、空頭、中性三種模式吃完全相同的區間與格數，投入資金同為 10,000 USDT，唯一差別就是方向。資金費率用 OKX 實際結算值逐次計入。

單一區間的一次結果說服力不足，所以主結果是滾動視窗：每 3 天起一個 30 天視窗，四個幣種共 200 個樣本，再按期間內買入持有的漲跌幅分成上漲 / 盤整 / 下跌三類。

成交判定：單根 K 線內的路徑不可知，收黑的 K 線走 開→高→低→收，收紅走 開→低→高→收。這個假設會不會撐起結論？下面穩健性一節用 5m / 15m / 1H 三種解析度交叉驗證過，差異在 0.2 個百分點內。

02

單一區間實測

先看最直觀的：從今天往回推 30 / 90 / 180 天，各跑一次。同一列的三種模式共用同一組網格參數。

03

200 個滾動視窗的分布

單次結果只是一個抽樣。把視窗滾起來，兩片點雲的形狀才是重點——多頭網格的收益率幾乎就是市場漲跌幅的一次函數，R² 高達 0.88。

04

錢從哪裡來

把報酬拆成兩塊：來回掛單賺到的網格利潤（已實現），和手上還沒平掉的持倉浮動盈虧。這一拆，事情就清楚了。

還有一個容易忽略的機制：順勢的網格會不斷實現利潤，逆勢的網格只會不斷累積倉位。多頭網格在上漲時把手上的貨一格一格賣掉，每賣一格就落袋一格；在下跌時卻是一格一格買進，帳上只有越來越大的部位和越來越深的浮虧。所以上漲組多頭網格的網格利潤（6.77%）明顯高於下跌組（2.22%）——不是它在跌勢中變懶了，是它根本沒有東西可以平。

05

空頭網格真的比較安全嗎

滾動視窗裡空頭網格平均贏，逆勢時也只虧 −3.03%，而多頭網格逆勢虧 −12.31%。看起來空頭網格結構上就比較耐打。這個推論是錯的，而且可以證明。

問題出在樣本：這 210 天裡，下跌視窗平均跌 −16.6%，上漲視窗只漲 +11.5%；而且跌勢更兇更直——下跌期間價格只有 55.6% 的時間待在網格區間內，上漲期間有 85.8%。空頭網格遇到的逆風本來就比較溫和。

要拆開「路徑形狀」和「網格數學」，就把每一段真實價格路徑繞進場價做幾何鏡像（p′ = 進場價² / p）：每個 −x% 精準翻成 +x%，時間節奏與震盪程度原封不動。然後拿空頭網格去跑鏡像路徑——這正是多頭網格在原始路徑上的嚴格對照組。

那為什麼實測空頭網格贏？因為加密市場「跌得快、漲得磨」。跌勢直接穿出網格區間繼續走，多頭網格滿倉硬吃；漲勢在區間內來回磨，空頭網格一邊虧一邊還在收網格利潤。這是這段期間的市場性格，不是空頭網格的優勢——市場性格會變，數學不會。
06

180 天淨值曲線

同一組 BTC 網格參數，三種方向並排。價格軌跡單獨畫在上方共用同一條時間軸——刻意不做雙軸。

07

資金費率：小，但不是零

永續合約網格會持續持有部位，所以每 8 小時的資金費會累積。這是多頭網格獨有的一項結構性成本。

30 天量級只有零點幾個百分點，遠小於浮動盈虧，但方向是固定的：多頭網格長期付費、空頭網格長期收費。單一區間拉到 180 天，BTC 多頭網格的資金費成本是 −0.70%，DOGE 是 −1.07%——放在動輒 10% 以上的網格利潤旁邊不致命，但它是持續失血，不會因為行情好轉而回來。

08

穩健性檢查

結論會不會是某個參數選出來的？把每個關鍵假設換掉重跑一次。

最關鍵的一組是 K 線解析度：5m 與 15m 在同樣的兩個幣上，結果差 0.04 個百分點（多頭 0.59 vs 0.55，空頭 1.71 vs 1.68），1H 也只差 0.3 以內。單根 K 線的路徑假設沒有在製造利潤。格數、等差 / 等比、手續費、槓桿、視窗長度全部換過，多空的相對關係與「網格利潤接近對稱」都沒有動搖。

09

這份回測不能告訴你什麼

  • 樣本只有 210 天、四個幣種。期間整體偏空（買入持有平均 −1.71%），任何依賴市場方向的結論都不該外推。
  • 滾動視窗高度重疊。每 3 天起一個 30 天視窗，相鄰樣本共用 90% 的資料，所以「勝率 74%」不是 200 次獨立試驗的勝率，不能當統計顯著性看。
  • 假設全部以掛單成交、零滑價。真實網格在急速穿價時會有部分單子吃不到或被迫吃單，實際成交次數與費率都會比這裡差。
  • 沒有模擬止損、止盈與手動重啟。價格離開區間後就一直抱著。真實使用者多半會在某個時點認賠或重設區間，那會大幅改變尾端損失的分布。
  • 資金費率只有近 98 天完整。OKX 的歷史資金費率端點約只回溯三個月，200 個視窗中有 128 個涵蓋完整資金費；較早的視窗低估了這項成本。
  • 1x 槓桿、不含爆倉。合約網格用槓桿時，逆勢那條尾巴會直接變成強平，本回測的浮虧數字在高槓桿下沒有意義。

這不是投資建議。回測結果不預測未來報酬，實盤結果會因滑價、成交、參數與市場結構而不同。

10

重現

全部程式碼在 grid-backtest/，只用標準函式庫，不需要 API 金鑰。

# 1. 抓 OKX 公開資料（K 線 + 資金費率）
python3 fetch_okx.py --outdir data --days 210 --bar 15m

# 2. 引擎自我驗證（9 項合成路徑檢查）
python3 test_engine.py

# 3. 單一區間實測
python3 grid_backtest.py --datadir data --days 90 --lookback 30 --grids 50

# 4. 滾動視窗 + 市場狀態分組
python3 rolling_study.py --datadir data --window 30 --step 3 --out rolling30.json

# 5. 鏡像對照檢驗
python3 mirror_test.py --datadir data
資料取自 OKX v5 公開端點 /api/v5/market/history-candles 與 /api/v5/public/funding-rate-history， 抓取時間 —。所有數字皆由 grid-backtest/ 內的腳本重新計算產生，未經手動調整。
