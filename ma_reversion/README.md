# MU 夜盤均線回歸策略（MA Reversion, Taipei 08:00–16:00）

用 OKX 的 `MU-USDT-SWAP`（美光科技代幣化永續）資料，在**台北時間 08:00–16:00**（＝美東 20:00–04:00，美股夜盤）做均線回歸。**主要週期 15m**，另附 5m 版本作為對照。

---

## 一、先講結論

**邊際是真的，但薄，而且高度依賴波動度環境。不是可以放大槓桿的印鈔機。**

| 項目 | 15m（主）| 5m（對照）|
|---|---|---|
| 資料期間 | 2026-03-04 ~ 2026-08-07（上市至今，零缺口）| 同 |
| K 棒數 | 14,971 | 44,895 |
| 交易時段 | 113 個 session | 113 |
| 交易數 | 54 | 83 |
| 總報酬 | **+6.82%**（年化 16.8%）| +3.04%（年化 7.3%）|
| Sharpe | **2.23** | 1.18 |
| 最大回撤 | **-2.30%** | -2.64% |
| 勝率 / 獲利因子 | 61.1% / 1.98 | 55.4% / 1.37 |
| 成本佔毛利 | **15.8%** | 30.9% |
| **Walk-forward 樣本外** | **+6.25%**（37 筆，PF 2.56，DD -1.15%）| +1.76%（48 筆，PF 1.33）|
| 逐筆 t 值 | **+1.74** | +1.00 |
| Bootstrap P(總和≤0) | **3.3%** | 14.4% |

**但是**：扣掉 2026-07，其餘 39 筆合計只有 **+0.80%（t=+0.30）**，等於打平。詳見 [第六節](#六風險與限制必讀)——**下真錢前請先讀那節**。

## 二、為什麼是夜盤（整個策略的地基）

均值回歸要成立，需要價格偏離是**流動性雜訊**而非**資訊**。美股現貨時段的跳動大多資訊驅動、會延續；夜盤沒有現貨 order flow，偏離傾向回補。

各台北時段的平均 5 分鐘絕對變動：

| 台北時段 | 對應美東 | 平均 \|5m 變動\| |
|---|---|---|
| 21–23 時 | 現貨開盤 | 0.37% / 0.33% / 0.24% |
| 00–04 時 | 現貨午盤～收盤 | 0.15–0.21% |
| **08–16 時** | **夜盤** | **0.13–0.24%（平均 ~0.15%）** |

更關鍵的是**同一套規則、同一組參數，只換時段**（三個都是 8 小時、週一至週五）：

| 台北時段 | 對應美股 | 交易 | 報酬 | Sharpe | PF |
|---|---|---|---|---|---|
| **08–16（本策略）** | 隔夜 | 54 | **+6.82%** | **2.23** | 1.98 |
| 16–24 | 盤前 + 現貨開盤 | 71 | -1.05% | -0.25 | 0.94 |
| 00–08 | 現貨午盤 + 收盤 | 45 | -0.68% | -0.25 | 0.92 |

**均值回歸只在夜盤成立。** 這不是參數調出來的，是時段本質。

### 額外的結構性優勢：不付資金費

`MU-USDT-SWAP` 資金費在 **00:00 / 08:00 / 16:00 UTC** 結算。交易時段是 00:00–08:00 UTC，策略在 07:45 UTC（台北 15:45）強制平倉——**剛好卡在兩次結算之間，永遠不會付到資金費**。

## 三、訊號的統計證據

不是先寫策略再回測，而是先確認邊際存在。用**非重疊**事件（每次穿越只算一次）測「首次觸及 z 帶之後 N 根 K 的報酬」：

| 週期 | 錨定 | 門檻 | 方向 | 事件數 | 前瞻 2h 報酬 | t |
|---|---|---|---|---|---|---|
| 15m | 32 (8h) | 2.5 | 多 | 51 | +0.397% | +2.01 |
| 15m | 32 (8h) | 2.5 | 空 | 67 | +0.463% | +2.82 |
| 5m | 96 (8h) | 2.0 | 多+空 | 210 | +0.401% | **+4.21** |

**每個錨定長度、每個門檻、多空兩邊全部為正**——寬闊高原而非單點尖峰。

## 四、策略規則（15m）

### 資料與時段
- 標的 `MU-USDT-SWAP`，週期 **15m**
- 時段：台北 **08:00–16:00**，**週一至週五**（32 根 K/session）
  （台北週六 08:00 ＝美東週五 20:00，美股週已收，必須排除）

### 特徵
| 欄位 | 定義 |
|---|---|
| `ma` | **SMA(close, 32)**。32 根 15m ＝ 8 小時 ＝**剛好一個 session**，是結構選擇不是擬合 |
| `sd` | (close − ma) 的 32 根滾動標準差；此標的中位數約為價格的 **0.80%** |
| `z` | (close − ma) / sd ← **主訊號** |
| `atr` | Wilder ATR(5) ≈ 1h15m |
| `atr_pct_rank` | atr% 的一週（672 根）滾動百分位 |
| `slope_n` | MA 在 4 根（1h）內的漂移量，以 ATR 標準化 |

### 進場（`first_touch`）
只在 z **穿越** band 的那一根進場，一次延伸只做一筆：

- 多：`z ≤ -2.5` 且 `前一根 z > -2.5`
- 空：`z ≥ +2.5` 且 `前一根 z < +2.5`

濾網：
- 在時段內，且 **`bars_left ≥ 12`**（剩餘不足 3 小時就不開新倉）
- `|slope_n| ≤ 1.5`、`atr_pct_rank ≥ 0.10`、`|z| < 6.0`

**執行：掛限價單**，價格 = 該根收盤 ∓ 1 tick（掛被動側確保是 maker），存活 1 根 K，沒成交就取消、**不追價**。

### 出場（優先序）
1. **硬停損**：進場價 ∓ `4.0 × sigma`（sigma 取訊號那根的 `sd`）——盤中以 high/low 判定
2. **z 結構停損**：`|z| ≥ 6.0`
3. **時間出場**：持有滿 **8 根**（2 小時）→ 收盤價出場 ← **主要出場方式**
4. **時段強制平倉**：台北 15:45 那根收盤無條件平倉

沒有停利目標。統計顯示 drift 要 1–2 小時才長出來，設近停利只會在噪音裡被隨機截斷。

### 部位大小
以停損距離反推，單筆風險 = 權益的 **0.75%**，名目上限 3 倍槓桿。停損越寬部位越小，風險恆定。

### 為什麼參數不是網格冠軍
網格前 7 名的 Sharpe 落在 2.08–2.38，且**全部** `max_hold_bars=8`——是真高原不是尖峰。冠軍是 `z_entry=2.0`（74 筆，Sharpe 2.38），但事件研究顯示 |z| 落在 2.00–2.09 的邊際是 **+0.002%（t=0.01）**，等於白做。所以採用高原中段的 `z_entry=2.5`（54 筆，Sharpe 2.23）而非峰值。

## 五、設計過程中撞到的坑

這節比參數表有用，因為這些是「照直覺寫就會賠錢」的地方。

**1. 用 ATR 設停損 → 必被掃。** 5m 上 `sd/ATR` 中位數 = 1.80（15m 上 1.43）。要 fade 的偏離是 2σ，用 2×ATR 停損只給 0.55σ 容忍度。第一版勝率 34.9%、停損 126 次全虧。**所有距離都必須用 sigma 計價。**

**2. 成本是致命約束，taker 直接判死刑。**

| 執行方式 | 往返成本 | 換算 sigma（15m）| 5m 結果 |
|---|---|---|---|
| taker 5bps + 3bps 滑價 | 16 bps | 0.20σ | -1.64% |
| **maker 2bps（本策略）** | **4 bps** | **0.05σ** | **+3.04%** |

均值回歸本質是在提供流動性，**必須用限價單進場**。

**3. 停利設太近 = 在沒有邊際的時間尺度上採樣。** 第一版平均持有 25 分鐘，但 drift 要 1–2 小時。實測：`tp_sd=1.5` → Sharpe 0.91；純時間出場 → **2.23**。

**4. `bars_left` 必須用時鐘算，不能數資料筆數。** 回測沒事（資料完整），但**實盤最後一根永遠是 0，會擋掉所有進場**。

**5. 換週期必須等時換算。** 所有窗口參數都是「根數」，直接把 5m 的參數套到 15m 等於把錨定和持有期都拉長 3 倍——那不是同一個策略。`src/timeframe.py` 負責這件事。等時對照下 15m 只是溫和勝出（Sharpe 1.33 vs 1.18）；Sharpe 2.23 那一跳來自重新最佳化。

**6. 樣本內最佳 ≠ 樣本外最佳（兩次踩到）。**

| 選項 | 樣本內 | Walk-forward 樣本外 |
|---|---|---|
| SMA 錨定 | +6.82% / Sharpe 2.23 | **+6.25% / PF 2.56** |
| EMA 錨定 | **+7.92% / Sharpe 2.37** | +1.15% / PF 1.15 |

EMA 在樣本內每個變體都更好，樣本外卻崩掉。**已退回 SMA。** 同理，5m 版本若讓最佳化器連錨定長度都每折重選，樣本外從 +1.76% 翻成 **-1.95%**。

**7. 漂亮的分組統計不一定是有用的濾網。** 事件研究顯示邊際隨波動度百分位單調上升（最低分位 -0.132%/t=-0.85，最高分位 **+0.952%/t=+3.31**），且陡峭趨勢中歸零（最陡四分位 -0.008%）。但把這些做成濾網加進策略後，Sharpe 從 2.23 掉到 2.01（收緊波動）與 1.72（收緊斜率）——因為 `z_entry=2.5` 和 `min_bars_left` 已經隱含捕捉了同樣條件，額外濾網只是砍樣本。**唯一採納的是把 `vol_rank_max` 從 0.95 放寬到 1.0**（沒有證據支持排除最高波動區，而那正是最好的區間；樣本外 +3.91% → +6.25%）。

## 六、風險與限制（必讀）

**1. 獲利集中在單月。** 逐月報酬（佔權益 %）：

| 月份 | 筆數 | 報酬 | 勝率 |
|---|---|---|---|
| 2026-03 | 6 | +0.05% | 66.7% |
| 2026-04 | 10 | +0.27% | 50.0% |
| 2026-05 | 12 | **-0.28%** | 41.7% |
| 2026-06 | 10 | +0.70% | 70.0% |
| **2026-07** | 15 | **+5.88%** | 73.3% |
| 2026-08 | 1 | +0.06% | 100% |

**扣掉七月：39 筆、合計 +0.80%、t=+0.30 ——打平。** 最大單筆佔總利潤 31%，前三筆佔 62%（扣掉前三筆仍為 +2.53%，中位數 ≈ 平均數，所以不是單一肥尾撐起來的，但集中度確實高）。

**2. 邊際依賴波動度環境，而波動度在樣本期間一路上升。** 各月 session 內 ATR%：三月 0.352 → 七月 0.812。低波動的三、四月績效打平，高波動的六、七月貢獻幾乎全部利潤。事件研究也證實邊際隨波動度百分位單調上升。**如果 MU 回到低波動環境，這策略大概率不賺錢。**

**3. 樣本很薄。** 這檔 2026-03-04 才上市，只有 5 個月、113 個 session、54 筆交易。逐筆 t=1.74（bootstrap P(總和≤0)=3.3%）勉強達標，但信賴區間很寬。

**4. 空單扛起幾乎全部獲利**（空 +6.33% vs 多 +0.35%）。多空不對稱在 5 個月樣本裡無法判斷是結構性還是巧合。

**5. 財報跳空風險。** 美股財報通常收盤後公布（約台北 05:00–08:00），**正好落在交易時段開始前後**，而實際進場也確實集中在台北 8 點那一小時。財報跳空不是均值回歸，是資訊，會直接穿過停損。**MU 財報日前後應手動停用策略。**

**6. 成本結構是假設值。** maker 2bps / taker 5bps 是 OKX 永續 VIP0 一般費率，請用自己帳號的實際費率重跑。滑價 3bps 只施加在 taker 成交。

**7. 資本效率低。** 2.4 筆/週、單筆風險 0.75%、名目槓桿約 0.5 倍，大部分時間資金閒置。

**8. 未建模項目**：代幣化股票的交易暫停/下架風險、極端行情下限價單完全不成交、OKX 對股票代幣的特殊風控規則。

## 七、怎麼用

```bash
pip install -r requirements.txt
npm install -g @okx_ai/okx-trade-cli    # 市場資料來源，唯讀、免 API key

# 1) 抓資料（上市至今；15m 約 1 分鐘，5m 約 3 分鐘）

# 2) 回測（主策略）
python src/run.py --data data/MU-USDT-SWAP_15m.csv --params config/params_15m.json --tag 15m_base

# 3) 換時段對照（驗證夜盤假設）

    --session-hours 16 24 --tag 15m_evening

# 4) 參數敏感度（看高原，不是看冠軍）
python src/optimize.py grid --data data/MU-USDT-SWAP_15m.csv --params config/params_15m.json

# 5) Walk-forward（唯一值得相信的數字）
python src/optimize.py wf --data data/MU-USDT-SWAP_15m.csv --params config/params_15m.json \
    --train-days 60 --test-days 20

# 6) 看當下的即時訊號（唯讀，不會下單）
python src/signal_live.py --params config/params_15m.json --equity 10000
```

## 八、回測的執行假設（都往保守方向設）

- 訊號在第 *t* 根**收盤**成立，最快第 *t+1* 根才可能成交——無前視偏誤
- 限價進場只在後續 K 棒**真的觸價**時成交，成交在限價、收 maker 費、不計滑價；TTL 內沒成交就取消
- 停損盤中以 high/low 判定；**同一根同時觸及停損與停利，一律記為停損**
- 跳空穿越停損時，以停損價與開盤價中**較差**者成交
- 停損／時間／收盤出場走 taker + 滑價；只有停利掛單走 maker
- 同時只持有一個部位，不加碼，不留倉過夜
- 波動與 sigma 一律取**訊號那根**的值（成交那根的收盤在下單當下並不可知）

## 九、檔案結構

```
ma_reversion/
├── config/
│   ├── params_15m.json     # 主策略參數
│   └── params.json         # 5m 對照組
├── src/
│   ├── fetch_data.py       # OKX CLI → CSV（--after 反向分頁）
│   ├── features.py         # 指標、時段標記、bars_left（時鐘計算）
│   ├── strategy.py         # 訊號規則（向量化，回測與實盤共用同一份）
│   ├── backtest.py         # 逐 K 回測引擎（maker/taker 分離）
│   ├── metrics.py          # 績效指標與分組拆解
│   ├── timeframe.py        # 跨週期等時參數換算
│   ├── optimize.py         # 網格掃描 + walk-forward（網格自動跨週期換算）
│   ├── run.py              # 單次回測 → 報告
│   └── signal_live.py      # 即時訊號（唯讀）
├── results/                # 報告、逐筆交易、參數網格、walk-forward 明細
└── data/                   # K 線（gzip 版入庫，可離線重現）
```

`strategy.py` 的規則只寫一次、向量化。`signal_now()` 對即時資料尾端跑的是**同一段程式碼**，實盤與回測不可能對不上。

## 十、如果要繼續推進

1. **跨標的驗證（最高優先）。** 同一套規則套到其他 OKX 股票代幣永續（AAPL/NVDA/AMD…）。如果邊際真的來自「夜盤流動性雜訊」這個結構性原因，別的標的也該出現；只在 MU 上出現就是過擬合。**這是目前最有效的證偽方法，也能直接解決樣本量不足。**
2. **等更多資料。** 5 個月太少，再累積 6 個月後重跑 walk-forward。
3. **加財報日曆過濾**，自動停用財報前後的 session。
4. **改善進場成交率**，研究掛更深、延長 TTL、或允許小幅追價之間的取捨。
