## 二、為什麼是夜盤（這是整個策略的地基）

均值回歸要成立，需要價格的偏離是**流動性雜訊**而非**資訊**。美股現貨時段的跳動大多是資訊驅動的，會延續；夜盤沒有現貨order flow，偏離傾向回補。

資料支持這個判斷。各台北時段的平均 5 分鐘絕對變動：

| 台北時段 | 對應美東 | 平均 \|5m 變動\| |
|---|---|---|
| 21–23 時 | 現貨開盤 | 0.37% / 0.33% / 0.24% |
| 00–04 時 | 現貨午盤～收盤 | 0.15–0.21% |
| **08–16 時** | **夜盤** | **0.13–0.24%（平均 ~0.15%）** |

更關鍵的是**同一套策略、同一組參數，只換時段**的對照（三個都是 8 小時、週一至週五）：

| 台北時段 | 對應美股 | 交易 | 報酬 | Sharpe | PF |
|---|---|---|---|---|---|
| **08–16（本策略）** | 隔夜 | 83 | **+3.04%** | **1.18** | 1.37 |
| 16–24 | 盤前 + 現貨開盤 | 109 | -1.84% | -0.54 | 0.89 |
| 00–08 | 現貨午盤 + 收盤 | 53 | -4.16% | -2.37 | 0.46 |

**均值回歸只在夜盤有效，換到現貨時段直接翻負。** 這不是參數調出來的，是時段本質。

### 額外的結構性優勢：不付資金費

`MU-USDT-SWAP` 的資金費在 **00:00 / 08:00 / 16:00 UTC** 結算。交易時段是 00:00–08:00 UTC，策略在 07:55 UTC（台北 15:55）強制平倉——**剛好卡在兩次結算之間，永遠不會付到資金費**。

## 三、訊號的統計證據

不是先寫策略再回測，而是先確認邊際存在。用**非重疊**事件（每次穿越只算一次）測「首次觸及 z 帶之後 N 根 K 的報酬」：

| 錨定 MA | 門檻 | 方向 | 事件數 | h24 平均報酬 | t 值 |
|---|---|---|---|---|---|
| 96 | 2.5 | 多 | 103 | **+0.484%** | **+3.30** |
| 96 | 2.5 | 空 | 107 | **+0.322%** | **+2.62** |
| 96 | 2.0 | 多+空合計 | 210 | **+0.401%** | **+4.21** |

重點是**每個 MA 長度（48/72/96）、每個門檻（2.5/3.0/3.5）、多空兩邊全部為正**——是寬闊的高原，不是單點尖峰。這才是真實邊際的樣子。

按月拆（無成本）：+0.18% / +0.22% / **-0.09%** / +0.72% / +0.98% / +0.25%，6 個月有 5 個月為正。

## 四、策略規則

### 資料與時段
- 標的 `MU-USDT-SWAP`，週期 **5m**
- 時段：台北 **08:00–16:00**，**週一至週五**
  （台北週六 08:00 ＝美東週五 20:00，美股週已收，必須排除）

### 特徵
| 欄位 | 定義 |
|---|---|
| `ma` | SMA(close, **96**)。96 根 5m ＝ 8 小時 ＝**剛好一個 session**，是結構選擇不是擬合出來的 |
| `sd` | (close − ma) 的 96 根滾動標準差 |
| `z` | (close − ma) / sd ← **主訊號** |
| `atr` | Wilder ATR(14) |
| `atr_pct_rank` | atr% 的一週滾動百分位 ← 波動 regime |
| `slope_n` | MA 在 12 根內的漂移量，以 ATR 標準化 ← 趨勢濾網 |

### 進場（`first_touch`）
只在 z **穿越**band 的那一根進場，一次延伸只做一筆：

- 多：`z ≤ -2.0` 且 `前一根 z > -2.0`
- 空：`z ≥ +2.0` 且 `前一根 z < +2.0`

濾網（全部要通過）：
- 在時段內，且 **`bars_left ≥ 36`**（剩餘不足以走完 24 根持有期就不開——這條很重要，見第五節）
- `|slope_n| ≤ 1.5`（強趨勢中不做逆勢）
- `atr_pct_rank ∈ [0.10, 0.95]`（跳過死盤與爆炸行情）
- `|z| < 6.0`（已經離譜到不像回歸，放棄）

**執行：掛限價單**，價格 = 該根收盤 ∓ 1 tick（掛在被動側，確保是 maker），存活 3 根 K，沒成交就取消、**不追價**。

### 出場（優先序）
1. **硬停損**：進場價 ∓ `6.0 × sigma`（sigma 取訊號那根的 `sd`）——盤中以 high/low 判定
2. **z 結構停損**：`|z| ≥ 6.0`
3. **時間出場**：持有滿 **24 根**（2 小時）→ 收盤價出場 ← **主要出場方式**
4. **時段強制平倉**：台北 15:55 那根收盤無條件平倉

沒有停利目標。統計顯示 drift 要 24 根才長出來，設近停利只會在噪音裡被隨機截斷。

### 部位大小
以停損距離反推，單筆風險 = 權益的 **0.75%**，名目上限 3 倍槓桿。停損越寬部位越小，風險恆定。

## 五、我在設計過程中撞到的四個坑

這節比參數表有用，因為這些是「照直覺寫就會賠錢」的地方。

**1. 用 ATR 設停損 → 必被掃**
這檔 `sd / ATR` 中位數 = **1.80**。要 fade 的偏離是 2σ，用 2×ATR 停損等於只給 0.55σ 的容忍度。第一版勝率 34.9%，停損 126 次全數虧損。**所有距離都必須用 sigma 計價，不能用 ATR。**

**2. 成本是致命約束，而且 taker 直接判死刑**

| 執行方式 | 往返成本 | 換算 sigma | 結果 |
|---|---|---|---|
| taker 5bps + 3bps 滑價 | 16 bps | **0.39σ** | -1.64% |
| **maker 2bps（本策略）** | **4 bps** | **0.10σ** | **+3.04%** |

taker 的 0.39σ 成本，會把 1σ 停利的損益兩平勝率推到 **78%**——數學上不可能贏。**均值回歸本質上是在提供流動性，必須用限價單進場。** 這一項就值 2 個百分點以上。

**3. 停利設太近 = 在沒有邊際的時間尺度上採樣**
第一版平均只持有 5 根 K（25 分鐘）。但前瞻報酬研究顯示 15/30 分鐘尺度是純雜訊，drift 要到 60–120 分鐘才長出來。雙邊界太窄，等於在沒有訊號的地方反覆丟硬幣付手續費。

**4. `bars_left` 必須用時鐘算，不能數資料筆數**
原本用「距離資料末端還有幾根」，回測沒事（資料完整），但**實盤時最後一根永遠是 0，會擋掉所有進場**。已改為從時間戳推算到收盤時刻。同時 `min_bars_left` 要 ≥ 持有期，否則單子被收盤截斷，邊際會被稀釋掉（實測 +1.83% → +0.52%）。

## 六、風險與限制（必讀）

**1. 樣本很薄。** 這檔 2026-03-04 才上市，全部只有 5 個月、113 個 session、83 筆交易。任何結論的信賴區間都很寬。

**2. 損益高度集中在單月。** 淨利 +303 USDT 裡，七月一個月就貢獻 +357（其他月份加總為負）。拿掉七月，這策略是平的。這是最大的隱憂。

**3. Walk-forward 結果對「讓最佳化器碰多少東西」極度敏感。**
- 錨定長度固定為 96（先驗結構選擇）、只重新最佳化戰術參數 → 樣本外 **+1.76%**
- 連錨定長度也讓最佳化器每折重選 → 樣本外 **-1.95%**（重選成短錨定的那幾折正好是虧錢的折）

換句話說，這個邊際禁不起太多自由度。**不要再加參數去調它。**

**4. 分半測試不一致。** 固定參數下：前半段（3/4–6/15）**-1.00%**，後半段（6/15–8/7）**+2.86%**。可以解讀為邊際在增強，也可以解讀為兩段都是噪音。

**5. 財報跳空風險。** 美股財報通常在收盤後公布（約台北 05:00–08:00），**正好落在交易時段開始前後**。實際上有 34/83 筆進場集中在台北 8 點那一小時。財報造成的跳空不是均值回歸，是資訊，會直接穿過停損。**MU 財報日前後應手動停用策略。**

**6. 成本結構是假設值。** maker 2bps / taker 5bps 是 OKX 永續 VIP0 的一般費率，請用自己帳號的實際費率重跑。滑價 3bps 只施加在 taker 成交上。

**7. 資本效率低。** 3.75 筆/週、單筆風險 0.75%、名目槓桿約 0.3 倍，大部分時間資金是閒置的。

**8. 未建模項目**：代幣化股票的交易暫停/下架風險、極端行情下限價單完全不成交、OKX 對股票代幣的特殊風控規則。

## 七、怎麼用

```bash
pip install -r requirements.txt
npm install -g @okx_ai/okx-trade-cli    # 市場資料來源，唯讀、免 API key

# 1) 抓資料（上市至今，約 3 分鐘）
python src/fetch_data.py --inst MU-USDT-SWAP --bar 5m --start 2026-03-04

# 2) 回測
python src/run.py --data data/MU-USDT-SWAP_5m.csv --params config/params.json --tag base

# 3) 換時段對照（驗證夜盤假設）
python src/run.py --data data/MU-USDT-SWAP_5m.csv --params config/params.json \
    --session-hours 16 24 --tag evening

# 4) 參數敏感度（看高原，不是看冠軍）
python src/optimize.py grid --data data/MU-USDT-SWAP_5m.csv --params config/params.json

# 5) Walk-forward（唯一值得相信的數字）
python src/optimize.py wf --data data/MU-USDT-SWAP_5m.csv --params config/params.json \
    --train-days 60 --test-days 20

# 6) 看當下的即時訊號（唯讀，不會下單）
python src/signal_live.py --params config/params.json --equity 10000
```

`signal_live.py` 輸出範例：

```
MU-USDT-SWAP 5m   last closed bar 2026-08-07 12:40 Taipei (04:40 UTC)
  close    884.20
  anchor   MA96 = 886.78   sigma = 3.335
  z        -0.77   (band +/-2.0)

  -> no entry signal
```

有訊號時會直接給出限價價位、部位大小、停損價與時間出場時刻。**它永遠不下單**，要不要執行由你決定。

單項參數覆寫：`--set z_entry=2.5 --set max_hold_bars=36`

## 八、回測的執行假設（都往保守方向設）

- 訊號在第 *t* 根**收盤**成立，最快第 *t+1* 根才可能成交——無前視偏誤
- 限價進場只在後續 K 棒**真的觸價**時成交，成交在限價、收 maker 費、不計滑價；3 根內沒成交就取消
- 停損盤中以 high/low 判定；**同一根同時觸及停損與停利，一律記為停損**
- 跳空穿越停損時，以停損價與開盤價中**較差**者成交
- 停損／時間／收盤出場走 taker + 滑價；只有停利掛單走 maker
- 同時只持有一個部位，不加碼，不留倉過夜
- 波動與 sigma 一律取**訊號那根**的值（成交那根的收盤價在下單當下並不可知）

```
│   ├── fetch_data.py       # OKX CLI → CSV（--after 反向分頁）
```

## 十、如果要繼續推進

1. **等更多資料。** 5 個月太少，再累積 6 個月後重跑 walk-forward，是最有價值的一步。
2. **跨標的驗證。** 同一套規則套到其他 OKX 股票代幣永續（AAPL/NVDA/AMD…）。如果邊際是「夜盤流動性雜訊」這個結構性原因造成的，就應該在別的標的上也出現；只在 MU 上出現就是過擬合。這是目前最有效的證偽方法。
3. **加財報日曆過濾**，自動停用財報前後的 session。
4. **改善進場成交率。** 目前 169 個訊號只成交 83 筆（49%），可以研究掛更深、延長存活時間、或允許小幅追價之間的取捨。
